# 学生模块、琴谱分类与地图调整验收

## 已实现

- 学生琴谱与练习页：上传个人琴谱旁新增“查询曲库”，新窗口打开 https://imslp.org。现有上传、班级范围、练习和社区功能沿用原流程。
- 学生课程知识与答疑：撤下独立导航，旧 `/knowledge` 链接转到首页并打开知音助手。首页原机器人与所有学生页面的悬浮入口打开同一助手，含课程答疑、课程资料检索和来源链接。对话在收起、切换资料标签和客户端路由跳转时保留；刷新页面后重新开始，未写入浏览器持久存储。
- 教师继续从原知识管理入口维护课程资料。答疑复用 `/api/chat` 的资料检索、来源和超出收录范围提示。
- 琴谱产品分类移除难度、曲风，新增类型和时期。类型为协奏曲、圆舞曲、夜曲、弹奏曲、练习曲、奏鸣曲、前奏曲、赋格、变奏曲、其他；时期可填写“19世纪”“巴洛克时期”等，最多100字符。国内/国外、教学提醒、发布状态、班级范围保持。
- 教师/学生的表单、列表、筛选、预览和练习页同步新分类。历史琴谱未填写新分类时不推断旧值。
- 音乐史地图：时代工具栏横排，地图扩大；地图与人物卡共用一个面板，1024px起并排，手机纵向排列。人物简介、代表作、注解、来源直接显示；AI讲解按需打开。仅地图页面收窄侧栏，其他页面保持原宽度。聊天只滚动消息容器，不再带动整页跳转。

## 数据兼容与部署

本地新库包含 `scores.score_type` 与 `scores.period`，旧库启动时以增量方式添加，两次打开不会重复添加。历史 `difficulty`、`genre_id` 和曲风表物理保留，产品不再使用，避免破坏原有数据及引用；新建谱服务端填入旧难度列的兼容值，编辑不改写历史值。

远程 schema 与 `drizzle/0007_score_classification.sql`、迁移 journal、snapshot 已同步。远程部署须先应用该增量迁移，再发布使用新字段的应用。本轮未连接或修改线上数据库。

## 自定义音乐人物可行性评估

当前人物实际存储在 `src/lib/composers.ts` 静态数组中，地图是本地图片，点位是0–100%的示意坐标，并非联网抓取或地理编码。技术上可以支持自定义，建议先做教师维护：姓名、年代、时代、地域、简介、代表作、注解、HTTPS资料来源，以及在底图上点击选点。

头像可通过教师上传，缺少时使用姓名首字作为标识，无须依赖自动搜图。正式接入需补充人物表的本地/远程迁移、教师CRUD、学生可见性、头像文件授权，并将地图及 `/api/chat` 的静态人物读取统一到服务端数据入口。现有上传文件授权仅识别琴谱、练习、提交等用途，不能直接把教师私有上传当作公开人物头像。

本报告记录最初的可行性评估阶段。后续已按用户授权实施教师自定义人物，详情及验收见 `../map-musicians-2026-10-23/verification.md`。自动找头像、同名识别和历史地点自动定位仍未新增，避免把自动匹配结果当作已确认的音乐史资料。

## 外部验证边界

IMSLP按钮验收确认跳转目标和新窗口行为，未代表该站在用户网络中的可访问性。合成会话验收不代表真实超星登录；未知问题SSE使用实际本地回退，人物聊天布局若使用受控SSE样本将由结果文件明确标注，不代表外部模型服务联调通过。

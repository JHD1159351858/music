# 登录姓名与本人资料验收

实现将超星认证中心已验票的 `displayName` 映射为姓名，`name` 映射为学工号／登录名，`orgName` 映射为学校。若姓名回退为学工号或 UID，不将其标为真实姓名。资料存入独立私有表 `auth_identities`，账号显示优先使用真实姓名，社区仍使用原昵称。

## 通过的验证

- 定向 ESLint、TypeScript 检查与生产构建通过。
- 认证、会话、数据持久化和权限相关测试 25/25 通过；先复现姓名被丢弃的问题，再验证修复。读端字段白名单也先复现扩展字段外泄，再验证过滤。
- `scripts/testing/auth-profile-smoke.mjs` 的 7 组 HTTP 联调通过，完整使用应用的登录、回调和教师密码接口；覆盖一次票据、state、身份不信任前端字段、刷新、进程重启持久化、退出以及教师待验证权限。
- CUA 浏览器通过教师入口发起模拟认证、输入合成教师密码，工作台顶部显示认证姓名，点击姓名可查看完整本人资料。
- 学生入口同样显示认证姓名；学生侧栏与公共首页均有「我的资料」入口。学生资料弹窗沿用黑金主题，教师弹窗沿用后台浅色主题。
- 浏览器未记录 warning/error；截图见 `teacher-profile.png` 与 `student-profile.png`。

## 验证边界

联调使用独立临时 SQLite、5005 应用端口和 5006 模拟认证中心。截图中的姓名、学校、学工号均为验收样例，没有将其写入正式教学数据库。本轮没有重新登录真实超星账号，也没有部署或修改认证中心。

已有会话不会凭空获得原先未保存的资料，需要退出后重新通过超星认证一次。认证中心未提供的字段显示「未提供」；头像、院系、专业、手机和邮箱没有被假装成已接通字段。

本地 SQLite 自动创建新增私有表。远端数据库使用时需应用 `drizzle/0005_auth_identities.sql`，迁移启用 RLS 并仅授权服务端角色；本轮未连接或迁移远端数据库。

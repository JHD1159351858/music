# 学生登录白屏与静态资源修复

日期：2026-10-16。

## 原因与修复

- 5000 端口的旧 Next 进程仍返回旧构建 HTML，而 `.next` 已被更新。复现时 CSS `4442e2a2eb7297cb.css` 与页面 JS `a71b1b478631b969.js` 返回 500，旧背景请求返回 404；5003 对应的新构建资源正常。
- 停止两个生产进程后统一构建，再同时启动 5000 与 5003，确保页面、脚本与静态资源匹配。启动文档补充了重建前停止全部生产服务的要求。
- `0.0.0.0` 与 Next 内部请求 URL 的来源不一致，会导致登录 POST 被拒绝。`next.config.ts` 为本机 5000／5003 增加 Host 限定的临时跳转，自动转到对应 localhost，保留路径与查询参数。采用配置路由，避免 Next 把中间件同源跳转相对化形成循环；未放宽 Origin 或身份校验。

## 验证

- 生产构建与 `next.config.ts` ESLint 通过。
- 两个端口各 17 个 CSS／JS／首页图片请求全部为 200。
- 两个端口均验证 `/` 登录参数及 `/practice?tab=queue`：0.0.0.0 返回 307，Location 正确保留端口、路径和参数。
- 实际浏览器从 `http://0.0.0.0:5000/` 自动进入 `http://localhost:5000/`；点击学生入口，通过当前配置的认证中心完成回调后进入 `/practice`。页面显示学生身份与 4 份测试琴谱，客户端错误日志为空。
- 以上验证使用当前认证中心和已存在的浏览器认证状态；没有输入或记录账号密码、票据、Cookie 或共享密钥。

HTTP 证据：`student-login-assets.json`。浏览器截图：`student-login-fixed.png`。测试琴谱内容是既有功能演示数据，不代表真实教学成果。

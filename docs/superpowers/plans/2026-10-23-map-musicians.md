# 自定义地图音乐家实施计划

**Goal:** 教师在中国/欧洲地图选点、添加和管理自己的音乐家，学生查看，资料同步用于知音人物讲解。

**Architecture:** 保留内置人物数组，以受会话保护的 `/api/map-musicians` 合并内置与数据库人物。所有响应点位统一为完整底图0–100%的归一化位置。教师自定义人物即时对已登录用户可见，仅创建者可修改/删除，内置人物只读。现有地图缩放和拖动继续使用。

**Tech Stack:** Next.js 16、TypeScript、shadcn/ui、SQLite / Supabase、Drizzle、pnpm。

## 明确的范围

- `MapMusician` 延用 Composer 的姓名、年代、时代、地域、简介、代表作、注解、来源和头像字段，增加 `origin`、`map_kind`、`teacher_id`、`avatar_file_id`。
- 自定义表持久保存信息、JSON来源数组和完整底图x/y。新库、旧库自动建表、远程schema、迁移及meta同步；不删除既有表或人物。
- POST/PATCH校验文字长度、0–100有限坐标、地图对应时代、HTTP(S)来源、头像所有权和栅格图片类型；不信任请求中的教师身份或任意头像外链。
- 教师点击“添加音乐家”进入选点模式。缩放/拖动后仍能准确点选；拖动与双指手势不会误新增。选点后表单填写，保存后显示人物卡；编辑支持重新选点，删除须确认。
- 学生没有管理控件，服务端同样拒绝学生写入、跨教师修改及修改内置人物。
- 头像复用 `/api/upload`，只有已被人物引用的头像对其他登录用户开放。替换/删除前检查所有业务引用，避免误删仍使用的文件。
- `/api/chat` 依据服务端人物ID查资料，不把前端传来的姓名或简介当作依据。无头像用姓名首字显示。
- 不新增学生投稿、自动找图、地理编码、审核发布或世界地图等流程。
